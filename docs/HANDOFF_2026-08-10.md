## Completed in this handoff

- Play supports a visible 1–50 planet quantity slider and custom quantity
  entry. The TargetCursor integration was removed.
- Expedition success states are rendered after ticket purchase and reveal
  receipt confirmation.
- My Planets now uses a responsive list-detail layout:
  - Revealed NFT cards and the detail panel show identity, type,
    minerals/day, linked drawing status, pixel preview, and deterministic
    ticket traits.
  - Unrevealed entries intentionally expose only the linked drawing status and
    a `MINT` action. They do not render a name, preview, type, minerals, or
    deterministic traits.
- Drawing status is queried through the typed Megapot Data API integration.
  The UI only maps its known historical states (`active`, `settled`), otherwise
  displaying `DRAWING STATUS UNAVAILABLE` rather than inventing an on-chain
  lifecycle state.

## Important boundaries

- Keep `TICKET_SOURCE` as `MEGAPLANETS_V1` and retain Base Sepolia as the
  target until mainnet is explicitly authorized.
- Ticket eligibility and proof remain on-chain; the Data API is used only for
  historical drawing status. Do not treat an API response as mint eligibility.
- Preserve the allowance-gated unlimited USDC policy: compare the exact required
  allowance before each action, approve the route spender with `maxUint256` only
  when insufficient, then refetch allowance after a successful approval receipt.
  Keep the receipt-confirmed transaction UI.
- Minting requires the voucher service configuration and canonical ticket
  provenance (`originTxHash` plus `logIndex`).
- Do not expose secrets or commit local environment files.
